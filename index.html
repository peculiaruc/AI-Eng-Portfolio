Project case studies

Each project is a story: the problem, the path through the system, the AI piece, and the part I owned.

01 / BOOTCAMP PROJECT

How a request moves

  1. User
  2. JWT auth
  3. Express API
  4. Permissions
  5. PostgreSQL

Health check at /health. API docs at /api-docs.

Problem

People cannot ask questions of their files until the server knows who they are and which documents they own.

Solution

DocuChat is that server: accounts, document records, and conversations, documented with Swagger and covered by tests.

AI component

A signed-in user opens a conversation and sends a message. The API checks the thread belongs to them, validates the body with Zod, and returns the message on that conversation.

My contribution

Authentication, admin permissions, tests, and the README. I also stopped the environment file from being tracked so secrets stay off GitHub.

Challenges

Access control. A user can read their own document. Someone else gets a not-found response unless they hold the manage permission.

Technology

  • TypeScript
  • Express
  • Prisma
  • PostgreSQL
  • JWT
  • Zod
  • Swagger
  • Vitest

What I learned

A chat product is an access-control problem first. The model is only useful after login, ownership, and a stable API exist.

GitHub, DocuChat repository

02 / GROUP PROJECT

How a request moves

  1. Shopper
  2. Web UI
  3. FastAPI
  4. Assistant
  5. Database

Team repository: aiffone/pricebot.

Problem

A store owner setting up a shop and a customer trying to buy need different help, often at the same time.

Solution

Pricebot is an e-commerce platform: catalogue, inventory, cart, orders, and a chat assistant that knows whether you are shopping or setting up a store.

AI component

The assistant helps find products, walks a store owner through setup, suggests items, and answers questions about orders and delivery. The reply depends on shopping context or onboarding context.

My contribution

Landing page and interface updates in the shared repository, including a landing-page pull request merged into main.

Challenges

The public page had to stay coherent while catalogue, cart, and assistant routes were changing in the same codebase.

Technology

  • Python
  • FastAPI
  • SQLAlchemy
  • SQLite
  • Alembic
  • JWT
  • Pydantic

What I learned

An assistant is one route in a larger system. Products, orders, and auth still have to work when the chat is the feature people notice.

GitHub, Pricebot repository

Engineering approach

I start from the user task, design the API around it, and keep auth and data ownership boring and explicit.

  1. Understand

    Name the user and the task.

  2. Design

    Sketch the routes and the data.

  3. Build

    Ship a small working path.

  4. Test

    Cover the path that can break.

  5. Deploy

    Document how to run it.

  6. Improve

    Tighten permissions and errors.
